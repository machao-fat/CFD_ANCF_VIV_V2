# Phase 1K.13-B — Experimental RBF displacement-path trace

## Result and scientific boundary

**Classification: `RBF_NOT_RECEIVING_DISPLACEMENT`**, specifically at the RBF solver's cylinder `pointDisplacement` input in this one-window experimental run. Structure wrote four distinct, nonzero trial displacements, yet every recorded cylinder point boundary value entering RBF was exactly zero. The RBF moving-control values, interpolated displacement and calculated mesh-point displacement were zero as a direct consequence. This rules out a nonzero input being lost *inside* the RBF interpolation for the observed calls. It does **not** identify whether the upstream loss is in the Fluid adapter's numerical `readData`, assignment to `cellDisplacement`, transfer to `pointDisplacement`, or their timing. The qualified adapter was not instrumented, so its numerical read remains unobserved. Phase 1K.11 remains `REVIEW_REQUIRED` for production adoption.

Only one physical window was run; it converged on attempt 4 (three rollbacks), with both participants exiting 0. No second window, FSI continuation, parameter change or rerun was performed. This experimental result is not HH06 validation and is not a production RBF qualification.

## What this resolves, and what it does not

The RBF solver was called with zero cylinder point displacement throughout the captured first window. It had no nonzero displacement to interpolate; this supports `RBF_NOT_RECEIVING_DISPLACEMENT` at its input boundary, **not** `RBF_INPUT_RECEIVED_BUT_MESH_NOT_MOVED`. It is more specific than the earlier accepted-output-only finding. However, the qualified Fluid adapter's numeric `readData` buffer was not logged; preCICE's mapping message records an event, not its vector payload. This evidence therefore cannot assign the upstream defect uniquely to preCICE read, adapter field selection, cell-to-point propagation, or checkpoint/write ordering. Nor can one diagnostic window establish the exact behavior of all 25 historical windows. A separately authorized audit of the qualified adapter's actual displacement-field update path is the next causal layer; no adapter modification, production adoption, or additional run is performed here.

Artifacts include the experimental source and binary, scratch XML/dynamic mesh dictionary, `fluid.stdout` (full per-call trace), `structure_trace.jsonl`, `structure.stdout`, participant stderr logs, and `trace_summary.json`. Fluid/Structure exit codes were both 0; no worker or participant process remained and no socket file remained. The source worktree had no tracked modifications; this report and experimental evidence remain untracked pending review.
