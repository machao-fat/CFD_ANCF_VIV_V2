# Phase 1K.16C — Adapter displacement-field contract design

**Classification: `POINT_DISPLACEMENT_CONTRACT_CONFIRMED`.** For the verified HH06 RBF implementation, the authoritative mesh-motion input is the cylinder boundary of the registered `pointVectorField pointDisplacement`. `cellDisplacement` is **not** an RBF input or a physical restart state. It is an adapter-side face-center staging field in the existing adapter design. The qualified binary can create this auxiliary field when absent; the Phase 1K.16B experimental source does not, causing its pre-coupling abort. The recommended *next experimental implementation* is Option A—restore adapter ownership of this auxiliary field while keeping `pointDisplacement` as the only RBF-facing displacement. This is a design decision, **not** an implemented or runtime-qualified repair.

The HH06 `system/preciceDict` uses `locations faceCenters`, `readData (Displacement)`, `namePointDisplacement pointDisplacement`, and `nameCellDisplacement cellDisplacement`. Fluid preCICE has 200 two-component face-center values (400 scalars); the Phase 1K.13-B RBF diagnostic recorded 400 cylinder point-boundary vectors. **Face data therefore need a defined face-to-point transfer, not an assumed one-to-one vertex assignment.** The candidate adapter implements this using `primitivePatchInterpolation::faceToPointInterpolate` from the cylinder face field to the point patch. This geometrical transfer is required; a registered *volume* intermediary is an implementation choice.

## Field ownership and active-chain contract

```text
preCICE Displacement at Fluid-Mesh face centers (mapped, absolute, metres)
    → adapter-owned face-center staging / face-to-point interpolation
    → registered pointDisplacement.cylinder boundary (absolute, metres)
    → RBFMeshMotionSolver::solve() after correctBoundaryConditions()
    → cylinder control displacements → interpolated newPoints
    → current mesh points = points0 + newPoints
```

`pointDisplacement` is owned as a mesh-motion field by the OpenFOAM RBF `displacementMotionSolver`/case and is the single authoritative value consumed by RBF. The adapter may *write its cylinder boundary* at the appropriate implicit read-time but must not create a second authoritative point displacement, alter RBF parameters, or treat `cellDisplacement` as the actual mesh state. `cellDisplacement`, if retained, is an adapter-owned scratch/diagnostic `volVectorField` carrying the received face-center displacement and must be dimensionally length, initialized from the zero-displacement 30.0 s release, registered before checkpoint discovery, and checked against the cylinder patch geometry. It must never be mapped from old-mesh point indices or mistaken for an independently measured release state.

The current experimental source's `FSI::Displacement::read()` writes each face value to `cellDisplacement.cylinder` and interpolates that patch into `pointDisplacement.cylinder`; its generic `write()` for face-center displacement also references the cell field. For this HH06 Fluid participant only `readData (Displacement)` is configured, but removing the cell field from the generic class would need a separate assessment of its writer path. The qualified binary's missing-field creation path and accepted-time `cellDisplacement` outputs show why Option A is the closest implementation contract; the source of that binary remains unknown.

## Options

| Option | OpenFOAM ownership / RBF compatibility | Retry and rollback consequences | Decision |
| --- | --- | --- | --- |
| **A. Adapter creates/manages `cellDisplacement`** | Adapter registers an auxiliary `volVectorField` when absent, validates an existing one, and keeps the current face-center → point-patch interpolation. RBF still reads only `pointDisplacement`. Matches the qualified binary's observed missing-field branch and the experimental class's face-center API. | Register before `setupCheckpointing()` so both auxiliary and point fields can be snapshotted. On retry restore mesh/physical fields, then apply the **new** preCICE endpoint displacement to both fields; on acceptance use the new-window start sample. Check that field assignment is not undone by `correctBoundaryConditions()` and that rejection does not leave old point/mesh state. Creation/lifetime and patch types must be specified and tested; do not simply copy binary behavior without source qualification. | **Recommended for the next isolated experimental implementation**, because it closes the specific startup gap with the least change to the face-center transfer contract. The extra field is required by this adapter implementation, not by RBF physics. |
| **B. Case/restart provides `cellDisplacement`** | A zero field file at `30/` could document an initial auxiliary state, but an on-disk file alone does **not** register a `volVectorField` in `mesh.objectRegistry`. The RBF port only requires/constructs `pointDisplacement`; `pimpleFoam` does not automatically load arbitrary volume fields. A separate loader/owner would still be necessary. | Duplicates release-state data and can become stale across mesh transitions or accepted/rejected writes. If a dedicated loader is added, its construction order, dimensions, patch types and checkpoint participation reduce to Option A's obligations in another layer. | **Not sufficient as a standalone repair.** Do not add a fabricated restart field merely to satisfy `lookupObject`. |
| **C. Adapter writes `pointDisplacement` directly** | Eliminate the registered volume intermediary for the HH06 reader; use a local face-sized buffer and explicit face-to-point interpolation into the existing cylinder point patch. Closest to the conceptual `preCICE → pointDisplacement → RBF` chain. | Fewer authoritative-looking fields, but more adapter redesign: handle generic face-center writer assumptions, patch interpolation on serial/parallel meshes, checkpointed point boundary and mesh points, and value persistence after `correctBoundaryConditions()`. Any direct face-to-point rewrite must remain absolute rather than accidentally accumulating displacement across retries. | **Potential long-term simplification**, not the narrow next experiment; requires its own source-level and offline qualification before runtime. |

## Required invariants before another runtime authorization

1. A startup-only scratch check must prove the selected experimental adapter can construct or find its staging field **without changing the frozen 30.0 s restart**, then prove dimensions, registration, cylinder patch size/type and initialized zero values. This is separate from the Phase 1K.16B failed run; no rerun was done here.
2. In an offline/synthetic mapped-data test, each of 200 received face vectors must be represented exactly once in the staging face patch, then converted to the cylinder point boundary with the verified interpolation. The point field—not the cell field—is the asserted RBF input. Test nonzero uniform x/y and a nonuniform face pattern, including finite values and coordinate convention.
3. For an implicit retry, assert `readData(Displacement, dt)` returns the just-exchanged iterate; restore physical mesh/flow/point-field checkpoint first and then apply this new absolute interface iterate. Check both the point patch **before and after** RBF's `correctBoundaryConditions()`, controls, `newPoints`, and actual mesh coordinates. For an accepted boundary, assert `readData(..., 0.0)` and no stale rejected-trial contamination.
4. Checkpoint tests must include `pointDisplacement` boundary/internal/old-time state, mesh points and any auxiliary `cellDisplacement` state; a registered field created *after* checkpoint discovery is unacceptable. Saved accepted-time fields alone are not sufficient proof of rejected-trial motion.
5. Preserve separate experimental library name/SHA/Build ID and the qualified `26ad…` adapter. Require a new, specifically authorized bounded attempt only after these gates; do not infer Phase 1K.11's 25-window result is repaired.

**Stop condition:** design only. No source/configuration edit, build, OpenFOAM, preCICE, ANCF or FSI run was performed in Phase 1K.16C.
