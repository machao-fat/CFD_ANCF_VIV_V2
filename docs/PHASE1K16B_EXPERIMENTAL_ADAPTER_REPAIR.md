**Classification: `ADAPTER_REPAIR_INCOMPLETE`.** The separately named adapter built and loaded, and a two-fake-participant preCICE 3.4.1 read-time probe passed. The sole authorized one-window Fluid/Structure diagnostic **failed before preCICE initialization and before any physical coupling attempt**: the selected clean upstream adapter requires an already registered `volVectorField cellDisplacement`, which the frozen 30.0 s new-mesh restart does not provide. Consequently, no experimental adapter displacement read, point-boundary update, RBF input, or mesh motion was qualified. The run was not repeated.

## Experimental lifecycle patch and visibility

The patch keeps upstream `writeCouplingData → advance`, checkpoint restore/write, result-write and timestep-adjustment order. Immediately after `advance()` it snapshots `requiresReadingCheckpoint()` and `isCouplingTimeWindowComplete()`. After the existing checkpoint and timestep operations, while coupling is still ongoing, it selects the *completed* step length for a retry or unfinished substep and `0.0` for an accepted window boundary, then calls `readCouplingData(selectedOffset)`. The completed length is captured **before** `advance()` so a later timestep adjustment cannot change the offset of the just-completed exchange. It reads initial coupling data at `0.0` after `initialize()` and before the initial physical checkpoint. It does not read after final coupling shutdown.

Experimental-only `PHASE1K16_READ_OFFSET`, `PHASE1K16_RECEIVED` and `PHASE1K16_POINT_BOUNDARY` logs expose the selected offset, returned vector max-absolute component, and cylinder point-boundary max norm. The selected source's existing `FSI::Displacement::read()` is supposed to assign face-center data to `cellDisplacement` and interpolate it to `pointDisplacement`. That path was **not reached in the real diagnostic**.

Window 2 showed the same distinction. The first two *offline probe* attempts failed because the fake participants had omitted required preCICE checkpoint-action queries; these scripts were corrected before the passing third probe. This is a **preCICE API semantic test**, not a direct execution of the OpenFOAM adapter's `readCouplingData` branch.

The experimental library's distinct basename, ELF exports/registration symbol, `ldd -r`, and `dlopen` passed preflight. ## Sole one-window attempt and first failure

Evidence: `evidence/phase1k16b_adapter/run-20260924T114746Z-c2245ff/`. The scratch `system/controlDict` loaded the experimental adapter by absolute path; the scratch `constant/dynamicMeshDict` used the already-built, separately identified Phase 1K.13-B diagnostic RBF library (`4a739721bfaa4734151e79bca285545d6934b2f5a9450080a5e833542a4c84ee`) to make internal mesh motion observable without changing its settings. `/proc/<Fluid PID>/maps` captured both experimental libraries and did not report loading the qualified adapter. OpenFOAM 10 loaded the RBF TPS mover, p/U and kOmegaSST, and constructed `Fluid_0000`'s preCICE Participant.

At `Adapter::configure → FSI::FluidStructureInteraction::addReaders → FSI::Displacement::Displacement`, the experimental upstream implementation called `mesh.lookupObject<volVectorField>("cellDisplacement")`. OpenFOAM aborted because the registry contained only `Force` and `U` as volume vector fields. The untouched restart includes `30/pointDisplacement` but **no `30/cellDisplacement`**. This is a source/case registration compatibility gap discovered before initialization, not evidence that the new retry offset is wrong and not an ALE/Fluid instability.

Fluid exited by `SIGABRT` (`-6`). The orchestration guard terminated the waiting Structure process (`-15`) and recorded the reason; neither participant completed a coupling attempt or physical window. `structure_trace.jsonl` was not created, no `30.0002` output directory exists, and the scratch `30/` remained byte-identical to its preserved source. No retry/accepted offset log, nonzero Fluid read, point-boundary update, RBF input or mesh-point motion could be measured. `process_cleanup.json` records Fluid PID `478614`, Structure PID `478615`, observed child PIDs, loaded library paths and exits; subsequent checks found no remaining participant/worker process or socket contents. There was **exactly one Fluid/Structure diagnostic launch** and no repair-and-rerun.

## Decision

`ADAPTER_REPAIR_INCOMPLETE`: source and binary identity separation, build, registration/load, configuration parsing up to FSI reader creation, and the independent preCICE read-time semantic gate are established. The required real displacement chain is **unqualified**. Do not promote this experimental library, modify the qualified adapter, or infer that RBF motion is repaired. A separately reviewed next phase must resolve whether `cellDisplacement` should be constructed by the scratch case/mesh-motion setup or the selected adapter source, preserving the physical checkpoint and point-field contract, before authorizing another runtime attempt. No 5- or 25-window run and no parameter tuning followed.
